# 2026 포트폴리오 보완 기록

## 현재 구현 상태 (2026-10-11)

- 랜딩·로그인·메인·상세 화면은 라이트 기본값의 저장형 다크모드를 제공합니다. 데스크톱 가로형 배치를 유지하고 작은 화면의 일부 세로 배치, 버튼 줄바꿈 방지, 공통 포커스·움직임과 reduced-motion을 적용했습니다.
- 담당·전체 환자는 이름/환자번호/진단·병실·알레르기·낙상·격리, 간호기록은 내용·기간·카테고리·작성자·중요 여부로 필터링합니다. 인수인계는 내용/작성자·기간·근무조·수기/AI·상태를 필터링합니다. 필터는 조회된 목록에 클라이언트에서 적용합니다.
- 수기·AI 초안을 서버에 임시저장하고 다시 열어 수정·승인합니다. 승인 후 작성자 수정도 가능하며 원본 AI와 수정본, 버전별 스냅샷을 보존합니다. 초안은 작성자 전용, 승인본·이력은 같은 부서 조회입니다.
- 운영 배포는 Flyway 마이그레이션 → Hibernate validate → 건강 상태 확인 순서입니다. 기존 DB의 최초 기준선 등록·백업·실패 대응은 저장소 `deploy/database/README.md`를 따릅니다. 기존 MariaDB를 보존하는 로컬 실행은 `local` 프로필입니다.
- 최신 API는 저장소 `swagger.yaml` 1.3.1, DB 개요는 `assets/db.png`입니다. 소개 GIF는 2026.10.11 현재 UI 기준입니다. 설계 개념 그림의 후속 기능은 구현 범위와 구분해서 확인하세요.

## 목표

기존 기능 시연형 프로젝트를 병동 간호 업무, 환자안전, 기록 무결성, 기존 EMR 연계를 설명할 수 있는 포트폴리오로 보완한다.

## 제품 범위

MediFlow는 완제품 EMR이 아니라 다음 업무를 담당하는 연계 모듈이다.

1. 담당 환자의 안전정보와 최근 상태 확인
2. 오더 수행, 투약, 바이탈, I/O, 간호기록 조회·입력
3. 근무조 데이터를 기반으로 인수인계 초안 생성
4. 간호사의 검토·수정·승인을 거친 최종 인수인계 저장

접수, 입퇴원, 원무, EDI 청구, 수술, PACS, 약제, 진료정보교류는 현재 범위에 포함하지 않는다.

## 이번 보완에서 변경한 사항

- 종료된 Gemini 개발 모델을 환경변수 기반의 지원 모델로 교체
- AI 요청 URL의 API 키 로그 노출 제거
- AI 연결 및 응답 타임아웃 추가
- 빈 후보·빈 본문 등 비정상 AI 응답 검증
- 외부 AI 전송 전 환자 이름과 차트번호를 가명 식별자로 치환
- AI 응답 수신 뒤 병원 서버에서만 환자 표시명을 복원
- 환자 상세 상단에 MRN, 부서, 알레르기, KTAS, 최근 활력징후를 고정 표시
- 환자 목록의 정보 밀도를 높이고 측정 시각을 명확하게 표시
- 인수인계 화면 진입 시 불필요한 전체 환자 조회 제거
- JPA 낙관적 잠금 버전을 추가해 동시 수정 덮어쓰기 방지
- JWT 문자열의 역할을 신뢰하지 않고 DB의 현재 계정 상태와 권한을 다시 확인
- 잠금·비활성 계정의 기존 토큰 사용 차단
- 간호사·의사는 같은 부서 환자만 조회·기록할 수 있도록 서비스 계층 접근 제어 추가
- 의사·관리자만 처방을 등록·삭제할 수 있도록 역할 기반 권한 적용
- 환자 임상정보 조회와 인수인계 승인 행위를 별도 감사 로그로 기록
- AI 인수인계를 원본 초안, 의료인 최종본, 모델 버전, 승인자·승인 시각으로 분리 저장
- 인수인계 화면에 AI 초안임을 표시하고 의료인의 검토·승인 단계를 추가
- 투약 수행을 원 처방과 직접 연결하고, 투약 기록 생성과 처방 완료를 단일 트랜잭션으로 처리
- 투약 수행 시 클라이언트가 보낸 약물정보 대신 서버의 원 처방 내용을 기준으로 기록
- 투약 수행자·수행 시각·특이사항과 처방 연결 ID를 보존하고 감사 이벤트 기록
- 진단과 무관한 무작위 일반의약품 시드를 제거하고 진단별 임상 맥락을 반영한 가상 처방 세트로 교체
- 카드형 SaaS 대시보드를 고밀도 EMR 작업화면으로 개편(28:72 분할, 행형 환자목록, 고정 환자안전 헤더)
- 처방 화면을 상태별 건수와 처방·용법·수행 열을 가진 투약 수행 워크리스트로 개편
- e약은요 API의 일반의약품 중심 범위를 명시하고 조회 성공·미수록·일시 장애를 구분해 표시
- e약은요 미조회 시 의약품 제품 허가정보 API의 목록·상세를 순차 호출해 전문의약품까지 대체 조회
- 프로젝트 설명을 완제품 EMR에서 병동 간호 연계 모듈로 정정

## 후속 보완 항목

- 간호기록 정정 전후 이력과 전자서명
- 미수행 오더, 지연 투약, 중요 검사결과 알림
- 담당 환자 배정 단위의 세부 접근권한과 응급 접근(Break-glass) 절차
- 감사 로그 조회·보존 정책과 위변조 방지
- 구조화된 진단, 알레르기, 병실·침상·입원 건 모델
- 테스트 범위 확대와 운영 배포 검증 강화

## 검증 원칙

- 모든 환자 데이터는 가상 데이터만 사용한다.
- AI 결과는 초안으로 표시하고 의료인의 확인 없이는 최종 기록으로 취급하지 않는다.
- 구현되지 않은 인증·보안·상호운용 기능은 문서에서 준수했다고 주장하지 않는다.


## 필터·정렬·안정성 마무리

최신순을 기본으로 하는 날짜 정렬, 테마 공통 DatePicker·드롭다운·시간 선택, 조회 취소와 재시도, 중복 저장 방지, 미저장 이동 확인을 적용했습니다. 임상 수정 요청과 응답에 version을 연결했고 입력 검증·오더 접근 권한·HTML 정제를 보완했습니다. 중복 개발 페이지와 튜토리얼형 변경 이력 주석, 임상·인증 디버그 출력을 제거했습니다. 검증된 범위는 [품질 검증 기록](10.QUALITY_AND_VALIDATION.md)에 정리합니다.
