# API 명세서

2026-10-11 기준 정적 OpenAPI 3.0.3 명세의 버전은 1.3.0입니다. 최신 원본은 [swagger.yaml](../swagger.yaml)이며 실제 컨트롤러·DTO가 구현 기준입니다. API 기본 주소는 로컬 `http://localhost:9005`, 운영 `https://api.mediflow-emr.cloud`입니다.

## 문서 보기

저장소에는 Springdoc 내장 Swagger UI가 설치되어 있지 않습니다. `http://localhost:9005/swagger-ui.html`을 제공한다고 가정하지 않습니다. Swagger Editor에 swagger.yaml을 열거나 공식 Swagger UI 컨테이너로 확인합니다.

```sh
docker run --rm -p 8081:8080 \
  -e SWAGGER_JSON=/swagger.yaml \
  -v "$PWD/swagger.yaml:/swagger.yaml:ro" swaggerapi/swagger-ui
```

## 인증과 응답

브라우저는 이메일 로그인 뒤 발급되는 HttpOnly `ACCESS_TOKEN`·`REFRESH_TOKEN` 쿠키로 인증합니다. JWT Bearer 헤더도 서버에서 지원합니다. 로그인 요청은 인증 갱신 재시도를 건너뛰고, 보호 API의 만료된 액세스 토큰은 갱신 후 한 번 재요청합니다. 쿠키 속성은 환경 설정을 사용합니다. 로컬은 host-only·SameSite=Lax·HTTP, 운영은 Secure·SameSite=None·설정한 도메인을 사용합니다.

주요 응답은 `{ "success": true, "data": ..., "message": null }` 형식입니다. 인증 등 일부 엔드포인트는 고유 응답 DTO를 사용합니다. 권한 오류는 403, 잘못된 요청은 400, 리소스 없음은 404, 오래된 기록 버전은 409입니다.

## 인수인계 API

| 메서드·경로 | 기능 |
|---|---|
| POST /api/handovers/ai-summary | 근무조 AI 초안 생성 |
| POST /api/handovers/ai-summary/patient/{patientId} | 환자 단위 재생성 |
| POST /api/handovers | 수기·AI 초안 또는 승인본 생성 |
| GET /api/handovers/department/{departmentId} | 같은 부서 승인본 + 본인 초안 조회 |
| PUT /api/handovers/{handoverId} | 작성자 초안 수정·승인 또는 승인 후 수정 |
| GET /api/handovers/{handoverId}/revisions | 최신순 수정 스냅샷 조회 |
| DELETE /api/handovers/{handoverId} | 작성자 기록 삭제 |

수기 초안 생성:

```json
{
  "departmentId": 1,
  "fromShiftId": 1,
  "toShiftId": 2,
  "sourceType": "MANUAL",
  "status": "DRAFT",
  "aiDraft": null,
  "finalSummary": "가상 환자 인수인계 초안"
}
```

AI 기록은 `sourceType=AI`, `aiDraft=원본`, `finalSummary=수정 내용`을 보냅니다. 승인 시 status는 APPROVED입니다. PUT에서는 저장된 부서·근무조를 유지하고 GET/저장 응답의 `version`을 추가합니다. 저장 응답은 id, version, 작성 구분, 상태, 원본·수정본, 작성자, 생성·수정·승인 시각 등을 포함합니다.

초안은 작성자만 조회·수정하고, 승인본은 같은 부서에서 조회하되 작성자만 수정합니다. 승인 후에는 원본·작성 구분을 변경하거나 초안으로 되돌릴 수 없습니다. 저장마다 수정 이력이 추가됩니다. 오래된 version은 409로 실패하며 프론트엔드는 편집 내용을 유지합니다.

## 목록 필터

필터는 현재 조회된 목록을 프론트엔드에서 조합합니다. 새 서버 검색 쿼리 API는 추가하지 않았습니다.

- 담당·전체 환자: 이름/환자번호/진단, 병실, 알레르기·낙상·격리.
- 간호기록: 내용, 시작·종료 날짜, 카테고리, 작성자, 중요 여부.
- 인수인계: 내용/작성자, 날짜, 근무조, MANUAL/AI, DRAFT/APPROVED.

날짜 범위는 한국 날짜 기준으로 양끝을 포함합니다. 결과 건수·초기화·검색 결과 없음 상태를 제공합니다. 서버가 허용한 부서·작성자 범위를 프론트엔드 필터가 확장하지 않습니다.

환자·임상기록·약품 API의 개별 요청 및 응답 필드는 swagger.yaml을 참고합니다. 운영 데이터로 Swagger UI의 쓰기 요청을 실행하지 않고 가상 데이터로 검증합니다.

## 기존 명세 누락 보완

이메일 check/verify-code/remaining-time, 의사·관리자 오더 등록·삭제, 오더 상태 변경, 품목번호 기반 약품 상세를 명세에 추가했습니다. 투약 요청의 원 처방 orderId·특이사항 notes, 부서 요약의 departmentId·shiftId·nextShiftId, 약품 조회 상태·함량도 현재 DTO에 맞췄습니다. 개발용 AiTestController는 RestController가 비활성화되어 문서의 운영 API로 추가하지 않습니다.


## 임상 기록 수정과 입력 오류

간호기록·V/S·섭취배설의 PUT은 조회 응답의 `version`을 전송해야 합니다. 누락·오래된 버전은 409, 환자 변경은 400, 작성자·현재 부서 접근 거부는 403입니다. 응답은 flush 이후의 갱신된 version을 포함합니다. V/S·I/O는 측정값을 하나 이상 요구합니다. 잘못된 JSON·파라미터와 오더 필수값·길이 오류는 400으로 반환합니다.

오더 약품 상세 조회와 삭제도 서버의 환자 부서 접근 검사를 거칩니다. 투약 응답의 canEdit는 원본 보존 정책으로 false입니다. 화면의 날짜 필터·최신순/오래된순은 접근 가능한 조회 결과에 적용하며 새로운 서버 정렬 파라미터는 추가하지 않았습니다.
