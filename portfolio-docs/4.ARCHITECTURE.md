# 현재 아키텍처 (2026-10-11)

이 문서는 저장소 코드와 배포 스크립트 기준입니다. AWS 리소스의 실제 운영 상태·성능 수치는 이 문서 갱신 과정에서 확인하지 않았습니다. 이전 개념도는 목표 구조를 포함할 수 있습니다.

## 요청 흐름

```text
브라우저 React/Vite
  → 로컬 /api 프록시 또는 운영 API 도메인
  → Nginx → Spring Boot (9005)
  → JWT 인증 + 서비스 부서·작성자 접근 제어
  → JPA/QueryDSL → MariaDB
```

화면은 환자 목록·상세 탭·인수인계를 하나의 대시보드에서 제공합니다. 전역 테마는 라이트 기본값·선택 저장 방식입니다. 목록 필터는 프론트엔드에서 접근 가능한 조회 결과에 적용합니다. API가 허용한 조회 범위는 서버에서 제한합니다.

브라우저 인증은 HttpOnly 쿠키입니다. JWT Bearer 헤더도 허용합니다. 로컬은 host-only/Lax/HTTP, 운영은 Secure/None/설정한 도메인입니다. 액세스 만료는 refresh 후 한 번 재요청하되 로그인 실패 자체는 refresh하지 않습니다.

## 인수인계 저장

```text
수기 작성 또는 Gemini 생성 → 원본 AI / 편집본 분리
  → POST 초안 저장 → GET 목록 → PUT 수정·승인
  → handover 갱신 + handover_revision 추가 (같은 트랜잭션)
  → 승인 후 작성자 수정도 새 이력 추가
```

version 기반 낙관적 잠금은 오래된 수정 요청을 409로 거절합니다. 초안은 작성자 전용, 승인본·이력은 같은 부서 조회입니다. 의료인 검토가 AI 결과를 자동으로 정확하게 보장하지는 않습니다. 외부 AI 요청은 이름·차트번호를 요청 내 가명으로 대체하며 자유 기록의 개인정보까지 자동 제거하지는 않습니다.

## 배포 흐름

프론트엔드 GitHub Actions는 빌드·S3 업로드·CloudFront 무효화를 수행합니다. 백엔드는 Java 21 테스트·bootJar → OIDC 인증 → S3 JAR 업로드 → SSM으로 EC2 deploy.sh 실행 → systemd 재시작·건강 상태 확인 순서입니다. 저장소의 현재 워크플로우는 SSH 배포를 사용하지 않습니다.

prod 시작 시 Flyway가 JAR 내 버전별 SQL을 실행하고 Hibernate validate 후 서비스가 준비됩니다. 최초 기존 DB 전환은 백업·대상 확인 후 baseline 설정이 필요합니다. 마이그레이션 실패는 서버 시작을 막습니다. JAR 롤백과 DB 롤백은 다릅니다. [배포 가이드](../deploy/aws/README.md), [DB 적용 절차](../deploy/database/README.md)를 따릅니다.

선택적인 Lambda 약품 캐시는 S3에 생성하며, 백엔드는 유효한 캐시가 없으면 외부 식약처 API로 대체 조회합니다. 클라이언트에 API 키를 노출하지 않습니다.

## 스키마와 검증

18개 JPA 엔티티 및 선택적인 flyway_schema_history를 사용합니다. [현재 DB 구조](5.DATABASE_DESIGN.md)를 참고하세요. 기존 MariaDB 보존용 local 프로필은 독립 설정 파일이며 schema validate만 수행합니다. 자동 테스트는 격리된 H2를 사용하고, 마이그레이션 테스트는 별도의 임시 MariaDB 스키마로도 실행할 수 있습니다.


## 클라이언트 상태와 저장 경계

목록 GET은 AbortController로 이전 요청과 언마운트 요청을 취소합니다. 대시보드는 계정 종료 시 환자·부서 상태와 진행 중 조회를 초기화합니다. 임상 입력은 환자 ID별로 마운트하고 미저장 상태를 공통 이동 확인 모달에 등록합니다.

날짜 필터·정렬·선택 메뉴는 공통 컨트롤과 순수 유틸리티로 분리했습니다. 오더의 약품 문서 표현은 DrugDocument로 분리해 수행·저장 흐름과 독립적으로 관리합니다. Axios 생성 팩터리는 동시 인증 갱신을 조정하며 만료 응답만 1회 재시도합니다. 네트워크·타임아웃 오류가 난 쓰기는 자동 재시도하지 않습니다.

서버는 부서 접근 확인 → 작성자 확인 → 요청 환자·버전 검증 → 변경·flush 순서로 임상 기록을 수정합니다. 낙관적 잠금 충돌은 409이며 클라이언트는 입력을 보존합니다. 현재 간호기록·V/S·I/O 정정 이력은 별도 구현되지 않았습니다. 인수인계만 스냅샷 이력을 보존합니다.
