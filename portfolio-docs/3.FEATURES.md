# 구현 기능 (2026-10-11)

MediFlow는 가상 환자로 병동 간호 업무를 체험하는 PoC입니다. 업무 시간 단축·임상 안전성·정확도는 실증한 성과로 주장하지 않습니다.

## 화면과 접근성

랜딩·로그인·메인·상세에 라이트 기본값의 저장형 다크모드를 적용합니다. 데스크톱은 환자 목록과 상세의 가로 배치를 유지하고 좁은 화면은 일부 세로 배치를 허용합니다. 버튼 텍스트 줄바꿈 방지, 공통 포커스, hover/전환 시간, reduced-motion을 사용합니다.

로그인 방식 선택 → 이메일 로그인 → 회원가입으로 이동합니다. 이메일 로그인 뒤로가기는 방식 선택, 회원가입 뒤로가기는 이메일 로그인입니다. 로그인·가입 입력은 동일한 테두리와 포커스 규칙을 사용하고, 인증 코드 입력과 비밀번호 표시 버튼에 접근성 이름을 제공합니다. 데모 안내는 유지하고 로그인 화면의 경고 문장만 제거했습니다.

## 환자와 간호기록 필터

| 화면 | 필터 |
|---|---|
| 내 담당·전체 환자 | 이름/환자번호/진단 검색, 병실, 알레르기·낙상·격리 여부 |
| 환자 간호기록 | 내용 검색, 기간, 카테고리, 작성자, 중요 여부 |
| 인수인계 | 내용/작성자 검색, 기간, 근무조, 수기/AI, 초안/승인 |

DatePicker·선택 메뉴·시간 선택은 공통 커스텀 컨트롤입니다. 테마, 포커스, 키보드 탐색, Escape·외부 클릭 닫기, 화면 경계에 맞춘 팝오버 위치를 통일합니다.

필터는 서버가 반환한 접근 가능한 목록에 적용합니다. 기간은 한국 날짜 기준 양끝을 포함합니다. 상세 필터 접기, 초기화, 결과 건수와 결과 없음 안내를 제공합니다.

## 날짜 정렬

간호기록·인수인계·오더·투약·V/S·섭취배설·검사결과는 **최신순**이 기본이며 최신순·오래된순을 선택할 수 있습니다. 정렬은 조회 원본을 변경하지 않고 동일 시각의 순서를 유지합니다. 누락·잘못된 날짜는 마지막에 표시합니다. V/S 증감과 그래프는 목록의 선택 정렬과 별개로 측정 시각을 기준으로 계산합니다.

## 환자 상세

담당·부서 환자를 선택해 MRN·진단·병실·알레르기·낙상·격리와 최근 활력징후를 확인합니다. 상세 탭은 오더, 간호기록, V/S, 섭취배설, 투약, 검사결과입니다. 간호기록은 HTML/Plain Text와 카테고리·중요 여부를 보존합니다. 처방과 연결된 투약 수행을 기록하며 약품 정보는 식약처 조회·허가정보 대체 조회·선택적인 S3 캐시를 사용합니다.

## 수기·AI 인수인계

1. 직접 수기 초안을 작성하거나 근무조 AI 초안을 생성합니다.
2. AI 초안은 환자별 편집·재생성이 가능하며, 직접 수정한 내용과 AI 원본을 분리합니다.
3. 서버에 임시저장한 초안을 목록에서 다시 열어 이어서 수정합니다.
4. 사람이 검토한 후 최종 승인합니다.
5. 승인 후 작성자가 다시 수정할 수 있고, 이전 내용·작성자·시각·버전은 수정 이력으로 조회합니다.

초안은 작성자만 조회합니다. 승인본·이력은 같은 부서에서 조회하되 작성자만 수정합니다. 승인 후에는 초안으로 되돌리거나 AI 원본·작성 구분을 바꿀 수 없습니다. 서버의 version 충돌은 409로 처리하고 편집 내용을 보존합니다. 새 저장과 이력 기록은 동일 트랜잭션입니다.

## 저장과 오류 복구

간호기록·V/S·섭취배설 수정은 조회한 version을 요구하고 오래된 요청은 409로 거부합니다. 기록 환자는 변경할 수 없으며 작성자와 현재 부서 접근 권한을 검사합니다. 실패하면 폼을 유지합니다. 저장 중에는 입력·중복 저장·화면 이동을 막고, 미저장 환자·탭 전환·로그아웃은 공통 확인 모달을 거칩니다. 새로고침·창 닫기는 브라우저의 미저장 확인을 사용합니다.

환자별 폼을 분리하고 이전 조회를 취소해 다른 환자의 응답이 섞이지 않게 합니다. 조회 실패 시 다시 불러오기를 제공합니다. 간호기록 HTML은 편집·표시 전에 정제하고 붙여넣기는 일반 텍스트로 받습니다. 투약은 원본 보존 정책상 수정 버튼을 제공하지 않습니다.

## 실행과 검증

React 19/Vite, Java 21/Spring Boot 3.5.6, JPA/QueryDSL, MariaDB를 사용합니다. 기존 로컬 DB는 validate 전용 local 프로필, 운영은 Flyway → validate 순서로 기동합니다. [API](6.API_DOCUMENTATION.md), [DB](5.DATABASE_DESIGN.md), [마이그레이션 안내](../deploy/database/README.md)를 참고하세요.

카테고리·작성자·병실·근무조·작성 방식·상태는 여러 값을 동시에 선택합니다. 같은 필드 안에서는 OR, 다른 필드 사이는 AND 조건으로 적용합니다. 선택 수와 체크 표시를 보여주며 전체 선택은 해당 필터 제한을 해제합니다.
