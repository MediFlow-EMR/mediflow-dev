# 향후 업데이트 계획 (Future Roadmap)

## 현재 구현 상태 (2026-10-11)

- 랜딩·로그인·메인·상세 화면은 라이트 기본값의 저장형 다크모드와 모바일 배치를 제공합니다. 공통 포커스·움직임과 reduced-motion을 적용했습니다.
- 환자 검색·병실·안전정보, 간호기록 내용·기간·카테고리·작성자·중요 여부, 인수인계 내용/작성자·기간·근무조·수기/AI·상태를 필터링합니다. 다중 선택은 같은 항목 안에서 OR, 항목 사이에서 AND이며 조회된 목록에 적용합니다.
- 간호기록·인수인계·오더·투약·V/S·섭취배설·검사결과는 최신순/오래된순을 선택합니다. 환자 목록은 KTAS 우선순위를 유지합니다.
- 상단 날짜·근무조로 과거 담당 환자와 부서 요약, 새 인수인계의 대상 근무조를 전환합니다. 환자 기본정보·최근 V/S는 현재 값이며 임상 탭의 기간 필터는 별도입니다.
- 수기·AI 초안을 서버에 임시저장하고 다시 열어 수정·승인합니다. 승인 후 작성자 수정, 원본 AI·수정본·버전별 스냅샷 보존을 지원합니다. 초안은 작성자 전용, 승인본·이력은 같은 부서 조회입니다.
- 운영은 Flyway → Hibernate validate → 헬스 체크 순서입니다. 기존 DB의 최초 기준선·백업·실패 대응은 [DB 전환 안내](https://github.com/MediFlow-EMR/mediflow-dev/blob/main/deploy/database/README.md)를 따릅니다. 로컬 MariaDB 보존은 `local` 프로필, 격리된 자동 테스트는 H2입니다.
- 최신 API는 [swagger.yaml](https://github.com/MediFlow-EMR/mediflow-dev/blob/main/swagger.yaml) 1.3.2, DB는 18개 JPA 엔티티입니다. 소개 GIF는 2026.10.11 운영 화면 기준입니다.

## 비전 (Vision)

메디플로우는 단순 기록 도구를 넘어 **AI 기반 간호 인력 지원 플랫폼**으로 발전하며, 간호사의 **업무 효율**과 환자 **안전**을 동시에 극대화하는 것을 목표로 합니다.

## Phase 1. 간호사 현장 업무 효율화 

**목표:** 사용자의 즉각적인 불편 해소 및 업무 시간 단축

![img.png](assets/phase1.png)

### 주요 기능 상세

| 기능 | 구현 방법 | 효과                              |
|-----|----------|---------------------------------|
| **신규 간호사 온보딩 챗봇** | 기존 ChatHistory 엔티티 + Gemini API 활용하여 EMR 사용법, 병원 정책, 기록 기준 안내 | **교육시간 단축**, 신규 간호사 현장 투입 속도 향상 |
| **약품 정보 즉시 조회** | 식약처 API 연동, 약품명 입력 시 효능·용법·주의사항 팝업 표시 | **투약 오류 감소**, 환자 안전성 향상         |
| **자동 근무표 배치 (수간호사용)** | AI 기반 스케줄링 (경력, 환자 중증도, 휴가 고려) | **수간호사 행정 업무 절감**, 근무 배치 공정성 확보 |
| **EMR 가이드 퀵링크** | "투약 기록 어디 봐요?" → 해당 탭으로 즉시 이동 | **정보 탐색 시간 제로화**, 업무 연속성 확보     |


## Phase 2. AI 기반 관리 자동화 및 CDS 확장 

**목표:** AI 역할 확장 - 기록 요약 → 관리 및 의사결정 지원

![img.png](assets/phase2.png)

### 주요 기능 상세

| 기능 | 구현 방법 | 효과                            |
|-----|----------|-------------------------------|
| **AI 임상 의사결정 지원 (CDS)** | 바이탈·I/O·검사결과 시계열 분석 → 패혈증 위험, 수액 보충 필요 등 경고 | 환자 위험 상황 **조기 감지**, 간호사 판단 지원 |
| **모바일 EMR 앱** | React Native/Flutter 기반 네이티브 앱, 환자 바코드 스캔 후 현장 기록 | **기록 정확도 향상**, 업무 공간 제약 해소    |
| **시스템 장애 즉시 대응** | EMR 오류 발생 시 IT 부서로 로그 자동 전송, Slack/Email 알림 | 다운타임 **감소**, 진료 연속성 확보        |

## Phase 3. 표준화 및 외부 시스템 통합

**목표:** 대형 병원 환경에 필요한 확장성 및 표준화 확보

![img.png](assets/phase3.png)

### 주요 기능 상세

| 기능 | 구현 방법 | 효과 |
|-----|----------|------|
| **HL7/FHIR 기반 데이터 연동** | HAPI FHIR 서버 구축, HL7 v2 메시지 파싱 모듈 개발 | PACS(영상), LIS(검사) 시스템과 완벽 통합 |

| **의료 장비 실시간 연동** | Bedside Monitor → EMR 자동 전송 인터페이스 (HL7 ORU 메시지) | 수기 입력 오류 **100% 제거**, 간호사 기록 시간 절감 |
